Bounded aggregate result-home forwarding prototype, 2026-10-21

Unregistered standalone module, validated through custom probe and integration test. Parent owns module registration, scheduling and independent review. Keep opt-in: only 6/4 retained QuickJS copies qualify and JS_CallInternal is unchanged.

crates/keel-opt/src/aggregate_return.rs: run(&mut Module) -> usize (number of eliminated complete copies). Tests include it by path, so the stage compiles without lib.rs or CLI edits.

Change only the selected direct call sret argument to a newly materialized StackAddr for the existing independent destination. Remove the exact copy loads and stores. Preserve the callee, its signature, all other call arguments and evaluation order. DCE can remove now-unused address computations; this prototype does not change frame layout or allocation.

Proof

  1. Callee is a defined local symbol, with an exactly matching call signature: no exported/interposable/declaration-only body assumptions. Single block, no variadic/returns-twice/scalar returns, 1..64-byte leading sret.
  2. Every result byte is written exactly once. All stores use nonvolatile sret-derived in-bounds constant-offset addresses. No load, call, intrinsic, inline assembly, trap, exception, address-to-integer conversion, other-address store, or sret-address observation is admitted. Other computations are explicitly whitelisted nontrapping scalar operations. This proves no capture and no observation; it does not infer nocapture from ordinarycall or small-register ABI.
  3. Source home is an exact-sized fixed slot. Whole-function operand closure admits only the selected call (sret argument once, no overlapping byval/source argument), bounded constant address derivation and the eliminated exact copy loads. Extra reads, writes, scalar observations, aliases through unknown operations, capture, indirect calls and cross-block copies reject.
  4. Destination is a distinct exact-sized fixed slot with alignment at least the source alignment. Its own address closure permits bounded ordinary loads/stores/address derivation. Any calls receiving destination-derived addresses must follow the completed copy in the same block. Such calls may capture: this remains safe because the proven constructor has no loads, calls or observers through which to see that capture, and the destination identity is unchanged.
  5. Between call and completed copy, at most 128 instructions: only constants, recognized stack/constant addresses, selected source loads and matching destination stores. Every byte copied once at identical offsets; every load result used solely by the eliminated copy. Moving writes across this interval cannot expose another observer or trap: both homes are valid fixed objects, the constructor is nontrapping and has no external effect, and no intervening effect is admitted.
  6. Whole-function rejection of every intrinsic (including FrameAddress and stack lifetime operations), inline assembly, invoke and direct/indirect returns-twice calls. Whole-module file/type debug metadata and all function debug homes reject. No narrowing of existing stack-forward escape rules.
  7. Hard budgets: 128 callee instructions, 512 callee values, 64 result bytes; 50000 caller instructions, 100000 caller values; 2000000 charged instruction+operand units for repeated closure scans; at most 128 matching instructions per candidate. One address walk, no fixpoint, recursive proof, call graph traversal, or CFG search. Budget exhaustion preserves valid partial progress.

Correctness and failure controls
  • yyjson: independent Python semantic digests for three corpora, eight valid edge documents and eleven strict invalid inputs. Native Clang O0/O2 and Keel None/Fast/Full pass.
  • LZ4: 174 boundary/corpus roundtrips and 1,892 assertions, byte equality after decode, malformed/truncated blocks and output guards. Clang O2 and Keel None/Fast/Full pass.
  • Both benchmark campaigns require application checks and exact Clang-reference outputs before timing: eight successful application configurations.
  • pugixml: 64 documents and 2,048 nodes; direct-source and exact-IR Clang references agree with the independent oracle. A reduced C++ case reproduces the importer rejection. Status remains blocked, not benchmark success.
  • Independent review found rejection/oracle/launch-error classification weaknesses; these were fixed. Eight focused Python failure-path tests and the Rust registry/schema test pass. Reviewed native validators were rerun.
Harness improvements and reproduction

The platform runner discovers manifests, prepares only selected applications, handles generic preparation/test commands and {gen} paths, and supports --checks-only and explicit candidate compiler/flag configurations. Failed configurations return failure. Invalid Clang reference checks abort before timing.

Run suite/benchmark_platforms.py --apps yyjson lz4 --configs keel-none keel-fast keel-full clang-O2 with --root, a fresh --work and frozen --keel, under suite/fast_opt_locked.py. The C++ pilot has its own validator and is excluded from native-C aggregates.

Raw commands, compiler/input/binary hashes, independent checks, samples and copied child evidence are retained under target/application-expansion-20261021. Companion JSON records the measurements and artifact hashes.

Single ARM host, ordinary ASLR/page backing, no LTO/PGO/native CPU tuning. Runtime includes startup, file/input preparation and driver work. No new x86 run; LinuxHost was not used.

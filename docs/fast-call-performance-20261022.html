What we implemented

Opt-in internal-fast-calls converts eligible private C helpers to cc(fast), removes their C-only extension contracts, and updates every direct caller. Exported/address-taken functions, tail endpoints, aggregate transport and assembly-bearing modules stay conservative.

Follow-up resolved the apparent QuickJS slowdown

A fresh 31-round repeat measured private-call cleanup at 0.999× for Fibonacci and 0.992× for sorting. Both intervals include equality. A byte-identical control also varied, so there is no sustained slowdown or demonstrated speedup here.

The smaller branch-only schedule produced byte-identical yyjson objects. It did not unlock the earlier cleanup gain and is not being promoted.

Correctness and decision

543 optimizer tests passed, 2 ignored. Eight native configurations each passed 131,072 byte/short patterns, including four unchanged controls. All five application correctness gates passed for Clang and both experiments.

Keep the private-call pass opt-in for its smaller machine code. Leave Fast and Full defaults unchanged. Next runtime work should target measured memory/loop bottlenecks and call-frame costs, rather than expecting extension cleanup alone to close the gap.

Measurement limits

Two warmups plus seven randomized, interleaved measured rounds; QuickJS follow-up has 31 rounds and a byte-identical Keel control. Native CLI timings include process startup. Bootstrap intervals use paired elapsed ratios, not independent claims of broad significance. Compilation has one measured sample per boundary and supports no stable compile-time conclusion. No native x86, remotes or LinuxHost were used.

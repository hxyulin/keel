What is included

  • Call chains: finalized ARM x9–x15 preservation proofs through bounded private direct calls; original leaf coverage protected.
  • Combined: call chains plus private two-word aggregate transport, stack cleanup and body-proven call/load reuse after Full.
  • Split allocation: proven preserved registers can retain clean spills over a call. Correctness validated separately; excluded from this application campaign.

  • 487 CLI/codegen tests passed, one ignored; optimizer rerun: 558 passed, two ignored. Final library/call-chain gate: 130 passed, overlapping earlier checks.

  • Native execution was ARM only. Both-target object checks do not substitute for Linux x86 execution.

Control change from the identical previous-Full executable:

  • quickjs/string: +1.9% (-0.3% to +6.6%)

  • ARM MacHost macOS only; no LinuxHost or remote work.
  • Default Full vs combined uses additional cleanup passes as well as private aggregate and call/load reuse. Causality is not assigned to an individual pass.
  • Seven measured interleaved screen rounds; selected 31-round follow-ups with identical baseline control. Intervals are exploratory bootstrap intervals, not multiplicity-adjusted.
  • CLI elapsed time includes process startup. Common preprocessed C and Clang link; no LTO, PGO or native CPU tuning.
  • Compilation has one measured round per boundary; use as screening data only.
  • Static instruction counts and preservation proofs do not establish runtime speedups.
Decision: retain the bounded implementations; keep aggregate, semantic call reuse and Split opt-in. The combined QuickJS result is worth a pass-by-pass ablation. Broader call-chain proofs alone do not establish a general application speedup. Significant Clang runtime gaps remain.

## Proof boundary inspected

The only identities recognized are adjacent, same-block
`i32 -> uext.i64 -> trunc.i32 -> uext.i64 -> inttoptr` and
`ptr -> ptrtoint.i64 -> trunc.i32`. Whole original-input admission precedes
`Body::new`, including actual runtime WASM32 verification; generated bytes still
receive final wasmparser WASM1 validation. Public APIs, admission code,
`runtime.rs`, conversion fallback and `ptradd` emission remain unchanged.

`InstData::for_each_operand` visits operand occurrences, including both operands
of a binary instruction, every call argument, return argument, branch condition,
switch selector and all arguments of every edge. It does not deduplicate edges
or values. Counts resolve aliases and saturate, so high fanout cannot wrap back
to single use. Layout-only counting agrees with emission's layout-only iteration.
The alias scan covers every allocated value, including unused aliases and aliases
of removed definitions. Every skipped intermediate must have exactly one
resolved occurrence, no alias relation and an exact raw link to the next cast.
This rejects escaping intermediate values through calls, control and phi copies.
Aliases of sources and final results are safe: source reads resolve normally,
while final results are stored in their distinct raw destination locals.

Only pure conversion definitions are omitted. The exact patterns cannot overlap
on skipped instructions: an interior conversion cannot start either pattern and
finish another matching chain there. Adjacent pure casts cannot overwrite the
source's distinct local or cross a call, volatile access, fault or CFG edge.
Original source producers, including retained aliased faulting producers, still
execute at their original positions. No observable producer, phi parallel copy,
frame allocation guard or normal-return stack restoration is removed.

For any i32 bit pattern, both zero extensions and both low32 operations in the
first pattern leave its low 32 bits unchanged. The getter's pointer already has
an i32 representation, so zero extension followed by low32 also preserves it.
An arbitrary i64 `inttoptr` followed by `ptrtoint.i64` is deliberately not an
identity: it still wraps to low32 and extends unsigned to i64. Signed extensions,
narrow truncations and interrupted/cross-block chains retain literal lowering.
Pointer addition continues wrapping the offset and sum modulo 2^32 before the
zero-offset exact-width memory access. No wrapping sum is absorbed into a Wasm
memory immediate.

## Stronger maintained counterexamples

Four added tests in `crates/keel-wasm/tests/low_bit_casts.rs` extend the six
candidate tests:

- Complete adjacent chains whose intermediate escapes afterward through repeated
  call arguments, duplicate-target branch edges, switch selector/edges or select
  arms retain all conversion operators and the expected shared values.
- A first intermediate with 257 occurrences stays materialized, checking the
  saturation boundary against a wrapping u8 count.
- Signed-extension near matches, a narrow i16 truncation and an intervening call
  remain literal. The narrow case differs semantically at 65536 and -1.
- Matched chains with aliased signed-division or volatile-load source producers
  still run those producers, retain the replacement source value, and preserve
  full-memory observations before division-zero, signed-overflow and OOB-load
  traps. Every trapped instance is discarded.

Decoded assertions establish activation and fallback, with independent BigInt
execution expectations. Existing controls cover negative/high-bit/2^32/
0xffffffff i64 inputs, unsigned pointer round trips, intermediate and final
aliases, cross-block phi transport, original unsupported/unexported admission,
actual four-byte WASM32 pointer initializers, wrap-before-access, complete 64-KiB
memory, canaries, volatile/call order, OOB stores without partial writes,
recursive/exhaustion behavior and repeated normal stack restoration.
